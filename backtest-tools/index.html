    技術指標與參數最佳化

    策略內用 self.Ind 計算技術指標，用 bt.Tools.optimize() 搜尋策略參數的最佳組合。以下範例中的 bt 即 api.bt。

    技術指標 self.Ind

    self.Ind 以增量方式計算指標：每根 K 棒呼叫一次，傳入到目前為止的完整序列，回傳累積的指標序列（list），取 [-1] 為最新值。

    def my_indicators(self, row):
    self.close_list.append(row['Close'])
    ma5  = self.Ind.rolling_mean(self.close_list, 5)
    ma20 = self.Ind.rolling_mean(self.close_list, 20)
    self.char['ma5']  = ma5[-1]      # 存進 self.char，show_monitor() 與 dashboard 的 K 線就會畫
    self.char['ma20'] = ma20[-1]
    return ma5[-1], ma20[-1]

    寫進 self.char 的值會畫在 show_monitor() 與儀表板的 K 線上，見 撰寫策略。

    呼叫方式

    • 每根 K 棒都呼叫一次。指標依呼叫次數逐根累積，只在部分 K 棒呼叫（例如放在 if 條件內）時，指標序列會與資料錯開。
    • 同一根 K 棒對同一個指標只呼叫一次。每呼叫一次，指標就前進一根；例如逐欄位計算特徵時，三個欄位都呼叫 ema(c, 15) 會前進三次，窗口錯位。同一個值要在多處使用時，計算一次後重複使用，或以當根的序號（row['index']）作為快取鍵，確保一根只計算一次。

    用 name 區分計算狀態

    每個指標都保存自己的計算狀態。未指定 name 時，依 window 與傳入的序列物件自動區分。同一條序列有多種用途時，例如同一份 close_list 要算兩個 5 日平均、但 min_period 不同，要用 name 區分，否則兩者會共用同一份狀態。

    self.Ind 是 Core 的類別屬性，所有策略實例共用同一份。同一個 Python 執行環境（例如同一個 Jupyter kernel）中執行多個 core 時，相同 name 的指標會共用狀態。要讓每個實例各自獨立，在 on_init 中建立新的指標物件：

    self.Ind = type(self.Ind)()

    指標一覽

    方法 參數 說明
    rolling_mean (ls, window, min_period=None, name=None) 移動平均
    rolling_max (ls, window, min_period=None, name=None) 移動最大值
    rolling_min (ls, window, min_period=None, name=None) 移動最小值
    rolling_std (ls, window, k=1, min_period=None, name=None) 與 ta-lib 的 STDDEV 相同：母體標準差（ddof=0）× k
    rolling_sum (ls, window, min_period=None, name=None) 移動加總
    ema (ls, window, alpha=None, name=None) 指數移動平均。alpha=None 為標準 EMA（α=2/(N+1)）；alpha=1/N 為 Wilder 平滑（ATR、RSI 使用）
    macd (ls, short_window=12, long_window=26, macd_window=9, name=None) MACD，回傳 macd_dif, macd_ema, macd_hist
    atr (high, low, close, window=14, name=None) ATR，與 ta-lib 相同，Wilder 平滑
    rsi (ls, window=14, name=None) RSI，與 ta-lib 相同
    stochastic (high, low, close, rsv_window=9, k_window=3, d_window=3, name=None) KD，與 pandas ewm(adjust=False) 的結果一致
    skew／kurt (ls, window, name=None) 移動偏度／峰度
    zscore／minmax (ls, window, eps=1e-9, name=None) 移動標準化／區間正規化
    median／tsrank (ls, window, name=None) 移動中位數／時序排名
    argmax／argmin (ls, window, norm=True, name=None) 窗口內極值的位置
    decay／slope／delta (ls, window, name=None) 線性衰減加權／斜率／差分
    corr／cov (a, b, window, name=None) 兩條序列的移動相關係數／共變異數
    katz (ls, window, name=None) 碎形維度
    shannon (ls, window, bins=8, name=None) 熵

    參數最佳化 bt.Tools.optimize

    先以隨機取樣探索參數範圍，再用 TPE 演算法搜尋，找出 CalmarRatio 最高的參數組合。

    語法

    api.bt.Tools.optimize(my_strategy, search_range, times=50, random_ratio=0.5)

    參數

    參數 型別 預設值 說明
    my_strategy 函式 — 必填。自訂策略函式，參數名稱與 search_range 的 key 相同，回傳 generate_report() 的結果（有 report 屬性的物件）
    search_range dict — 必填。參數範圍，格式為 {'名稱': [最小, 最大, 步長]}
    times int 50 總搜尋次數
    random_ratio float 0.5 前段隨機探索的比例，其餘次數以 TPE 演算法搜尋

    回傳

    最佳參數的 dict，例如 {'percent_in': 2.3, 'percent_out': 4}。

    • 評分是 rp.report 的 CalmarRatio（CAGR / abs(MddRatio)），NaN 視為 0。
    • 所有參數組合的結果存成目前資料夾的 optimize.xlsx（CalmarRatio 排在各 KPI 欄的最前面），執行結束後自動開啟。

    範例

    def opt(percent_in=2, percent_out=3):
    core = MyStrategy()
    core.percent_in  = percent_in       # 覆寫 on_init 設的 self.xxx
    core.percent_out = percent_out
    core.feed_data(df)
    return bt.generate_report({cfg: core})

arg = {'percent_in': [1, 5, 0.1], 'percent_out': [1, 10, 0.1]}
best = bt.Tools.optimize(opt, arg, times=50)

rp_best = opt(**best)                   # 用最佳參數重跑一次
print(rp_best.report)

    策略函式的寫法

    • 要搜尋的參數在 on_init 中設為 self.xxx，策略函式建立 core 後再覆寫。直接寫在 on_bar 中的常數無法從外部調整。
    • 每次呼叫都建立新的 core。core 會保存部位與統計，重複使用會累積前一次的結果。
    • 取樣值為整數時以 int 傳入（1.0 會傳入 1），否則為 float。window 這類需要整數的參數，在函式開頭用 int(x) 轉換。
    • 字串參數以索引搜尋，例如 'metric_i': [0, len(METRICS)-1, 1]，在函式內再用索引取出字串。
    • 要固定某個參數不搜尋時，用 functools.partial(run, metric='YoY') 先帶入該參數。

    使用建議

    Tip

    • 評分只看 CalmarRatio，偏好高報酬、低回撤，但不考慮交易次數，只交易 3 次且剛好都獲利的參數也可能得到高分。取得最佳參數後，檢查 rp.report 的 TotalTrades。
    • 最佳參數是在同一段資料上挑選出來的，在其他期間不一定成立。建議把資料分成前後兩段分別驗證，做法見 策略範例。

    錯誤處理

    錯誤訊息 原因 處理方式
    成功: 0組，接著出現 UnboundLocalError（best_params） 每一組參數執行時都發生例外，例外內容不會顯示。常見原因是策略函式收不到參數名稱，或回傳值不是 generate_report() 的結果 以任一組參數直接呼叫策略函式一次（例如 opt(percent_in=2, percent_out=3)），就會顯示實際的錯誤
    PermissionError（寫入 optimize.xlsx 時） 上一次執行自動開啟的 optimize.xlsx 仍在 Excel 中開啟，檔案被鎖定。錯誤在整輪搜尋結束、寫入檔案時才出現 再次執行前先關閉 optimize.xlsx
