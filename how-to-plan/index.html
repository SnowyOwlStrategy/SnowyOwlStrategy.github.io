    規劃研究流程

    從「想做一個策略」到可以交易的策略，中間需要資料清洗、特徵檢驗、防止資料洩漏等步驟。這頁說明六階段的研究流程，以及每個階段可以向 AI 助理提出的提問範本。提問技巧 說明單一需求的提問方式，這頁說明整個研究的規劃。

    為什麼需要規劃

    以 提問技巧 的選股輪動策略為例：「用月營收 YoY 選前 10 檔」這句話每個字都可以正確執行，結果卻可能大幅落後 0050。原因不在執行，而在於直接從想法跳到回測，略過了中間的資料清洗、特徵檢驗與防止資料洩漏。

    六階段流程

    ① 定義問題    你在賭什麼？用什麼衡量？
     ↓
② 資料盤點    有什麼、多長、什麼單位、什麼頻率
     ↓
③ 資料清洗    倖存者偏差、單位、對齊、極端值
     ↓
④ 特徵工程    原始欄位 → 可比較的分數
     ↓
⑤ 訊號驗證    在回測之前先確認特徵有用
     ↓
⑥ 回測        才輪到這一步

    略過其中任何一個階段，問題都會留在結果裡，而且程式不會報錯。錯誤訊息與相關說明見 錯誤訊息。

    定義問題

    開始前，先用一句話回答以下三個問題：

    問題 不明確的回答 明確的回答
    假設是什麼？ 「找會漲的股票」 「營收動能領先股價反應，公告後一個月有超額報酬」
    對照基準是什麼？ （未定義） 「0050 買進持有」或「加權指數」
    什麼結果算失敗？ （未定義） 「Sharpe < 1 或輸給 0050 就放棄」

    第三個問題特別需要事先決定。沒有預設的失敗標準，容易不斷調整參數直到結果好看為止，形成過度配適。

    提問範本

    我想驗證一個假設：⟨假設⟩
對照基準用 ⟨0050 / 加權指數⟩
如果 ⟨Sharpe < 1 / 輸給基準 / 交易次數 < 30⟩ 我就放棄這個方向

先幫我規劃流程，不要急著寫回測

    最後一句讓 AI 助理先提出流程規劃，而不是直接寫程式。

    資料盤點

    寫任何邏輯之前，先確認資料的範圍。

    要確認的四項

    項目 說明 參考頁面
    歷史長度 長度會變動，以 len() 確認。2026-10 台股日頻為 500 筆（約 2 年），「近五年」無法以日頻做到 資料期間與頻率
    單位 _千 ÷1e5 得億、_百萬 ÷1e4 得億。成交量整股是張、期貨是口 MSMP 資料表與欄位
    頻率與 index 型態 月營收 index 是字串 '2026-M08'，不是日期；季頻是 '2026-Q2' 資料期間與頻率
    資料日期 api.MSMP 只到前一交易日；美股比台股晚一天 矩陣資料 MSMP

    提問範本

    我要用 ⟨月營收 / 季財報 / 籌碼⟩ 做研究，先幫我盤點：
① 這張表有多長歷史、index 是什麼型態
② 每個欄位的單位是什麼
③ 資料日到哪一天
④ 有沒有「看起來有但其實沒有」的欄位

先不要寫策略

    範例：月營收的時間軸

    月_營收 index:  '2026-M08'  (字串，營收所屬月份)
INDEX['M']:     2026-09-10  (Timestamp，公告日)
                    ↑
            差一個月！8 月營收在 9/10 公告

    以營收所屬月份對齊會形成未來函數：用尚未公告的資料選股，回測結果會高於實際可達成的水準。

    資料清洗

    要處理的四項

    倖存者偏差

    pools = api.MSMP.list
# ❌ 只用現在還在市場上的
universe = pools['tse']

# ✅ 想清楚要不要含已下市的 145 檔
pools['delist']        # 已下市

    只用現存股票回測，等於事先知道哪些公司沒有下市，會系統性高估報酬。股池中是否納入已下市的股票（pools['delist']）要事先決定。

    股池純度

    universe = set(pools['tse']) - set(pools['etf']) - set(pools['KY']) - set(pools['DR'])

    ETF 沒有月營收、KY 股的財報認列方式不同、DR 是存託憑證，與一般股票混在一起排名沒有意義。

    單位

    # ❌ 成交額_百萬 當成千元
last_vol = tvol.iloc[-1] / 1e5        # 錯！只剩 1 檔通過

# ✅ 百萬 -> 億是 /100
last_vol = tvol.iloc[-1] / 100        # 對，569 檔通過

    成交額_百萬 換算成億要除以 100。若誤當成千元除以 1e5，過濾條件會從「篩掉流動性不足的股票」變成「幾乎全部篩掉」（569 檔變成 1 檔），程式不會報錯。

    極端值

    月營收 YoY 這類變化率會出現上萬 % 的值，反映的是分母接近零（去年同期營收趨近於零），而不是成長。只依數值排序時，這類公司會佔滿名額。先觀察分布的尾端（例如前 1%），再決定處理方式：設定上限、改用累積值，或加上規模門檻。

    提問範本

    在算任何特徵之前，先幫我做資料清洗：
① 股池要排除 ETF / KY / DR，並告訴我要不要含已下市
② 每個欄位的單位換算列出來給我確認
③ 檢查極端值分布，告訴我前 1% 長什麼樣
④ 檢查缺失值比例

做完給我一份「清洗前 vs 清洗後」的檔數對照

    「清洗前 vs 清洗後」的檔數對照可以看出每一層過濾刪掉多少股票，上述單位換算的問題就能從檔數異常發現。

    特徵工程

    原始欄位不能直接比較，要先轉成同一個尺度。

    常見做法

    做法 寫法 使用時機
    Percentile 排名 d.rank(axis=1, pct=True) 跨股票比較，不受極端值影響
    Z-score (d - d.mean()) / d.std() 需要保留距離資訊時
    分位數分組 pd.qcut(d, 5) 檢查單調性（第 1 組到第 5 組是否遞增）

    多因子合成

    sc = None
for tbl, col, direction in FACTORS:
    src = getattr(api.MSMP, tbl)
    d = getattr(src, col)
    # ★ 先套可交易遮罩再排名，母體才一致
    p = d.where(tradable).rank(axis=1, pct=True)
    p = p if direction == 'long' else 1.0 - p
    sc = p.fillna(0.5) if sc is None else sc + p.fillna(0.5)
sc = (sc / len(FACTORS)).where(tradable)
    要點 說明
    先套遮罩再排名 否則排名的母體包含買不到的股票
    反向因子用 1.0 - p 不使用負號
    缺值填 0.5 中性值，不給予加分或扣分

    對齊到換股日

    財報與營收的公告日不一定落在換股日。建議寫法：

    # ❌ 直接 reindex，公告日對不上換股日就全變 NaN
d = src.reindex(R)

# ✅ 先 union 再 ffill 再 reindex
d = src.reindex(src.index.union(R)).ffill().reindex(R)

    ffill 表示「使用最近一次已公告的值」，與實際交易時可取得的資訊一致。

    提問範本

    幫我把這些原始欄位轉成可比較的特徵：
⟨欄位清單，標註正向/反向⟩

要求：
① 用 percentile 排名，先套可交易遮罩再排名
② 反向因子用 1-p，缺值填 0.5
③ 財報對齊用 union → ffill → reindex，不要直接 reindex
④ 做完給我每個因子的分布統計和缺值比例

    訊號驗證

    這個階段在回測之前進行，目的是先確認特徵與未來報酬是否有關係。

    三項檢驗

    檢驗 做法 判讀
    IC（資訊係數） 特徵值與未來 N 日報酬的相關係數 絕對值 > 0.03 視為有訊號
    分組單調性 依特徵分 5 組，比較各組平均報酬 第 1 組到第 5 組要單調遞增
    換手率 W.diff().abs().sum(axis=1) 過高時報酬會被成本抵銷

    以 提問技巧 的選股輪動策略為例，跑完整個回測才發現選到的是財報異常的公司；若先做分組檢驗，在這一步就會看到最高分那組的報酬不是最好的。

    提問範本

    在回測之前先幫我驗證訊號：
① 算每個因子的 IC（特徵 vs 未來 20 日報酬）
② 按因子分 5 組，看各組平均報酬是否單調
③ 算換手率，估算成本會吃掉多少

如果 IC 太低或不單調，直接告訴我這個因子沒用，不用跑回測

    最後一句可以在訊號不成立時省下回測的時間。

    回測

    前五個階段完成後，回測本身的設定相對單純。

    要設定的三項

    【部位】固定金額（qty >= 1, unit=1）還是目標權重（qty < 1）？
        → 固定金額：capital 不生效、無複利
        → 目標權重：capital 生效、有複利
【成本】台股個股 fee=0.001425, tax_short=0.003, unit=1
        台股 ETF  tax_short=0.001
        台指期    fee=500, unit=200, tick_map=[(inf,1)]
【對照】generate_report(core_dic, benchmark=...)

    建議追問

    ① 扣成本前的毛損益是多少？成本佔投入資金幾 %？
② 回測期間實際是哪一段？

    日頻訊號進出頻繁時，總報酬可能是負的、毛損益卻是正的，虧損幾乎都來自交易成本。總報酬為負時，先看毛損益再判斷策略。

    完整的規劃提問範本

    一次說明整個流程：

    我想驗證：⟨假設⟩
對照基準：⟨0050 / 加權指數⟩
失敗標準：⟨Sharpe < 1 就放棄⟩

請按這個順序做，每一階做完先給我結果再繼續：

① 資料盤點——歷史長度、單位、index 型態、資料日
② 資料清洗——股池純度、單位換算、極端值分布、缺值比例
   ※ 給我「清洗前 vs 清洗後」的檔數對照
③ 特徵工程——percentile 排名、先遮罩再排名、union→ffill→reindex
④ 訊號驗證——IC、分組單調性、換手率
   ※ 如果訊號太弱就直接說，不要硬跑回測
⑤ 回測——目標權重輪動、正確成本、加 benchmark
⑥ 跑完告訴我這個規格有什麼缺陷

不要跳階段，也不要在②之前寫任何策略邏輯

    其中「每一階做完先給我結果再繼續」讓提問者在每個檢查點都能決定是否繼續，而不是到最後才拿到一個無法驗證的數字。

    流程檢查清單

    檢查項目 未處理時的影響 對應階段
    依六階段進行，不直接從想法跳到回測 問題留在結果中且不會報錯 全部
    事先定義失敗標準 參數一路調整到結果好看為止 定義問題
    決定股池是否包含已下市股票（delist） 倖存者偏差，高估報酬 資料清洗
    財報以 union → ffill → reindex 對齊 整片 NaN，或用到未公告的資料 特徵工程
    回測前先看 IC 與單調性 在無效的因子上花時間回測 訊號驗證
    追問毛損益與成本佔比 無法分辨虧損來自策略還是成本 回測
    參數最佳化後檢查 TotalTrades，並切前後兩段分別驗證 過度配適 回測
