    下單與成交

    策略的下單都經由 self.Condition：Global() 描述在什麼條件下送出什麼委託，set_STL() 等四個方法設定停損停利。 委託的掛單、更新、取消與撮合由引擎處理，成交價依委託型別與下一根 K 棒的開高低收決定。

    Condition.Global

    語法

    self.Condition.Global(triggered, add_qty, trade_price, trade_type,
                      cancel_triggered, rule, match_uid='')

    參數

    參數 型別 預設值 說明
    triggered bool — 觸發條件。True 時送出或更新委託
    add_qty float — 數量。正數為買進／建多，負數為賣出／建空。0～1 的小數代表投入資金的比例，實際口數依 config() 的 lot_size 換算；1 以上為固定數量，單位由 config() 的 unit 決定
    trade_price float — 委託價。0 代表市價
    trade_type PriceType — 委託型別，見下方「委託型別 PriceType」
    cancel_triggered bool — True 時取消此委託（依 rule／match_uid 找到委託）。不需要時傳 None 或 False
    rule str — 規則名稱。用來識別委託、對應 Position.rule，也是 set_STL() 等方法比對的依據
    match_uid str '' 要平掉的持倉 uid。'' 表示不綁定持倉：建立新倉，有反向部位時依序沖銷

    同一組 (rule, match_uid) 重複呼叫 Global() 會更新既有的委託，不會再送出一張新委託。要同時掛兩張不同的委託，使用不同的 rule。

    數量與資金的關係（比例下單、固定數量）見 商品設定與績效報告。

    範例

    # 進場：空手時送市價買單
self.Condition.Global(self.global_qty == 0, 1, 0,
                      self.PriceType.market_ioc, None, 'bk')

# 反手：多單訊號成立時一次補齊到 +qty，並以空單訊號作為取消條件
self.Condition.Global(long and self.global_qty < 1,
                      -self.global_qty + qty, 0,
                      self.PriceType.market_ioc, short, 'long')

    綁定特定持倉出場

    有多筆持倉時，不帶 match_uid 的出場單會依序沖銷，各筆持倉無法分別出場。要讓每筆持倉獨立出場，在 on_position 中以 P.uid 綁定：

    def on_position(self, P):
    if P.rule == 'bk':
        self.Condition.Global(True, -1, P.entry_price + 5,
                              self.PriceType.limit_rod, None, 'exit', P.uid)

    綁定的持倉已經平倉時，框架會自動撤銷這張委託。策略同時使用內建停損停利或反手時，自訂的平倉單以這種方式綁定，避免持倉已被平掉後又成交而反向建倉，見 撰寫策略。

    委託型別 PriceType

    以 self.PriceType.xxx 傳給 trade_type。

    值 說明 未成交時
    market_ioc 市價單，一定成交 —
    limit_ioc 限價單，只看下一根 K 棒 立即取消，不留單
    limit_rod 限價單（買在較低價、賣在較高價） 留單到之後的 K 棒
    stop_rod 觸價單（買在突破、賣在跌破，用於停損） 留單到之後的 K 棒
    compel_now 強制立即成交，不經撮合判斷，直接以指定的 trade_price 成交。價格不能填 0（會以 0 元成交），例如結算時填 row['Close'] —

    成交價規則

    在 on_bar 送出的委託在下一根 K 棒撮合，以下一根的開高低收判斷是否成交與成交價。

    下表以第 0 根開高低收皆為 100（在此下單）、第 1 根為開 100、高 110、低 90、收 100（用來撮合）實測：

    委託 成交價 說明
    market_ioc 買 100 下一根的開盤價
    market_ioc 賣 100 同上
    limit_ioc 買 @95 未成交 開盤 100 高於限價 95，IOC 不留單，直接取消
    limit_ioc 買 @105 100 開盤價已優於限價，以開盤價成交
    limit_rod 買 @105 100 同上
    limit_rod 買 @95 95 開盤未滿足，盤中最低 90 觸及，以限價成交
    limit_rod 買 @80 未成交（留單） 最低只到 90，未觸及 80
    stop_rod 買 @95 100 開盤 100 已越過觸價，以開盤價成交
    stop_rod 買 @105 105 開盤未觸發，盤中最高 110 穿越，以觸價成交
    stop_rod 買 @120 未成交（留單） 最高只到 110
    limit_rod 賣 @105 105 盤中最高 110 觸及
    stop_rod 賣 @95 95 盤中最低 90 跌破

    歸納如下：

    • 限價單（limit_*）：開盤價已優於限價時，以開盤價成交；否則盤中觸及限價時，以限價成交。
    • 觸價單（stop_rod）：開盤價已越過觸價時，以開盤價成交；否則盤中穿越觸價時，以觸價成交。

    跳空時的停損價

    stop_rod 遇到跳空越過觸價時以開盤價成交，模擬實際交易的滑價。以 stop_rod 停損時，大幅跳空的 K 棒會以開盤價出場，虧損可能大於設定的停損幅度。

    同一根 K 棒內成交

    只有使用 feed_tick()／feed_tick_df() 時，K 棒在形成過程中才會有同一根內成交的情況：

    情境 market_ioc 成交價
    在 on_bar 下單 下一根的開盤價
    在 on_intrabar／on_position 下單，且 K 棒仍在形成中 下一筆 tick 進來時的價格（同一根內）

    使用 feed_data() 時，每一列都是一根完整的 K 棒，沒有盤中過程，在 on_bar 下的市價單一律以下一根的開盤價成交。

    停損停利

    方法 說明
    self.Condition.set_STL(name, STL) 固定停損：價格從進場價往不利方向移動 STL%（例如 2.0）時出場
    self.Condition.set_PFT(name, PFT) 固定停利：價格從進場價往有利方向移動 PFT%（例如 5.0）時出場
    self.Condition.set_MoveLoss(name, DS) 移動停損：價格從持倉期間的極值價格回撤 DS% 時出場
    self.Condition.set_TGT_PFT(name, TGT, PFT) 目標追蹤：獲利先達進場價的 TGT% 後啟動，再從最高獲利點數回吐 PFT% 時出場
    • name 與進場時 Global() 的 rule 相同，停損停利會套用到該規則建立的持倉。
    • 這四個方法依當前持倉重算出場價並更新出場委託，要在 on_bar 中每根 K 棒無條件呼叫一次，不放在 if 內；沒有呼叫的 K 棒，出場價不會更新。
    self.Condition.Global(con1, 1, 0, self.PriceType.market_ioc, None, 'long')
self.Condition.set_STL('long', 2.0)
self.Condition.set_PFT('long', 5.0)
self.Condition.set_TGT_PFT('long', 2.7, 32.0)
self.Condition.set_MoveLoss('long', 5.0)

    出場價

    以多單為例（極值價 ＝ entry_price + P.max_earn），空單方向相反。

    方法 出場價 委託型別 出場單的 rule（多／空）
    set_STL(name, STL) entry_price × (1 − STL/100) stop_rod STL／STLs
    set_PFT(name, PFT) entry_price × (1 + PFT/100) limit_rod PFT／PFTs
    set_MoveLoss(name, DS) 極值價 × (1 − DS/100)，以極值價格的 % 計算 stop_rod DS／DSs
    set_TGT_PFT(name, TGT, PFT) 極值價 − max_earn × PFT/100，以獲利點數的 % 計算；需先滿足 極值價 ≥ entry_price × (1 + TGT/100) 才啟動 stop_rod TGT／TGTs

    進場價 100、價格最高到 120（max_earn = 20）時：

    輸出
    set_STL('bk', 5)          → stop_rod @ 95.0    = 100 × 0.95
set_MoveLoss('bk', 5)     → stop_rod @ 114.0   = 120 × 0.95        ← 極值價格的 5%
set_TGT_PFT('bk', 1, 30)  → stop_rod @ 114.0   = 120 − 20 × 0.30   ← 獲利點數的 30%

    set_MoveLoss 的 DS 以極值價格為基準，set_TGT_PFT 的 PFT 以獲利點數為基準，兩者的數值不能互相換用；上例兩者都是 114 只是數字剛好相同。

    保留的 rule 名稱

    停損停利的出場單以 match_uid=P.uid 綁定在個別持倉上，並使用上表的 rule 名稱。自行下單時不要使用 STL、PFT、DS、TGT，以及加上 s 的空單版本（STLs、PFTs、DSs、TGTs）。

    委託價依 tick_map 調整

    所有非 0 的委託價，包括限價、觸價、compel_now 的價格，以及 set_STL() 等算出的出場價，都會依 self.tick_map 四捨五入到合法的跳動單位。

    預設的 tick_map 是台股現股的規則，價格 1000 以上時以 5 為單位，台指期 18000 點附近的價格會被調整為 5 點的倍數。期貨策略要在 on_init 中設定：

    def on_init(self):
    self.tick_map = [(float('inf'), 1)]      # 台指期、小台：1 點

    以一支台指期均線策略（2017～2026，62 次結算）為例，未設定時結算的 compel_now 價格全部是 5 的倍數，每次最多偏差 2 點、累計 9 點。只使用市價單的策略影響較小；使用限價或停損委託的策略，每一筆委託價都會被調整。

    常用寫法

    用途 寫法
    空手時進場做多 1 口 Global(sig and self.global_qty == 0, 1, 0, PriceType.market_ioc, None, 'bk')
    有多單時全部平倉 Global(sig and self.global_qty > 0, -self.global_qty, 0, PriceType.market_ioc, None, 'bp')
    多空反手（一張委託同時平舊倉、開新倉） Global(long and self.global_qty < 1, -self.global_qty + qty, 0, PriceType.market_ioc, short, 'long')
    多空反手（拆成兩張委託） 先 Global(True, -self.global_qty, 0, PriceType.market_ioc, None, 'net') 平舊倉，再 Global(True, ±qty, 0, PriceType.market_ioc, None, 'bk'/'sk') 開新倉。損益與一張的寫法相同；一張的寫法會把舊倉的 exit_rule 標為新倉的規則名稱，拆成兩張則各規則的績效分開記錄。見 策略範例
    加碼（不論現有部位再加 1 口） Global(sig, 1, 0, PriceType.market_ioc, None, 'add')
    以資金的 30% 進場 Global(sig, 0.3, ...)，並在 config() 設定 lot_size
    低接（限價買在現價下方） Global(sig, 1, row['Close'] * 0.99, PriceType.limit_rod, None, 'bk')
    突破買進（觸價單） Global(sig, 1, self.H, PriceType.stop_rod, None, 'bk')
    每筆持倉獨立出場 在 on_position 中使用 match_uid=P.uid
    條件不成立時撤單 Global(..., cancel_triggered=撤單條件, ...)
    結算日強制平倉 Global(row['DateTime'] == row['Settlement'], -self.global_qty, row['Close'], PriceType.compel_now, False, '結算')
    收盤前平倉（不留倉） 判斷 row['DateTime'].strftime('%H%M') == '1345'，再用 market_ioc 或 compel_now 平倉
    連勝後加碼 在 on_bar 中讀取 self.stats.get('bk', {}).get('continue_wins', 0)
    只在特定時段交易 hm = row['DateTime'].strftime('%H%M')，以 '0900' <= hm <= '1100' 作為條件
