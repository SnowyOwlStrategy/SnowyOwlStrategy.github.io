    SWQuote.set_event 連線事件與事件碼

    所屬章節：即時行情 以 2026-08-21 盤中實際執行結果為準（StarWaveQuoteAPI 1.0.0.4） 事件序列是實際擷取；具名常數的缺口以原始碼與 AttributeError 雙向驗證

    Overview

    api.SWQuote.set_event(callback)     # callback(event: SWEvent) -> None

    set_cb 收行情資料，set_event 收連線層級的事件：連上、登入、訂閱成功／失敗、斷線。

    SWEvent 三個欄位：

    欄位 型態 說明
    event_code str 發生什麼事，11 種，見下表
    status_code str 結果代碼，'SW000'~'SW011'
    message str 完整訊息，格式 StatusCode: SWxxx, Detail: ...

    event_code（11 種）

    event_code 觸發時機
    connected 連上 StarWave server
    disconnected 斷線（主動或異常都算）
    login_ok 登入成功
    login_fail 登入失敗
    login_exhausted 所有可用通道都登入失敗
    login_not_attempted 連線前置檢查沒過，登入沒執行
    contracts_ready 商品合約資料備妥
    subscribe_ok 訂閱成功
    subscribe_fail 訂閱失敗
    unsubscribe_ok 取消訂閱成功
    unsubscribe_fail 取消訂閱失敗

    status_code（12 種）

    status_code 說明
    SW000 操作成功
    SW001 連線已中斷
    SW002 登入失敗
    SW003 訂閱請求失敗
    SW004 訂閱請求被拒絕
    SW005 取消訂閱請求失敗
    SW006 已達訂閱數量上限
    SW007 所有通道登入皆失敗，或因帳號層級錯誤停止重試
    SW008 這個連線物件沒有有效的登入驗證來源
    SW009 伺服器沒回傳可用的 channel
    SW010 缺少登入憑證（帳號或密碼為空）
    SW011 登入未執行，因連線前置檢查失敗

    具名常數不完整 —— 這是會咬人的地方

    so.SWEvent.event_code.* / so.SWEvent.status_code.* 提供可讀的具名常數， 但它們沒有覆蓋全部列舉值：

    底層列舉 具名常數 缺少
    event_code 11 9 LOGIN_EXHAUSTED、LOGIN_NOT_ATTEMPTED
    status_code 12 7 SW_LOGIN_EXHAUSTED(SW007)、SW_LOGIN_NO_AUTH_SOURCE(SW008)、SW_LOGIN_NO_CHANNEL(SW009)、SW_LOGIN_MISSING_CREDENTIALS(SW010)、SW_GATE_CHECK_FAILED(SW011) 
    so.SWEvent.event_code.LOGIN_EXHAUSTED
# AttributeError: 'EventCodeNamespace' object has no attribute 'LOGIN_EXHAUSTED'

    所以要處理登入類失敗（SW007~SW011）只能跟字面字串比：

    LOGIN_PROBLEMS = {'SW002', 'SW007', 'SW008', 'SW009', 'SW010', 'SW011'}

def on_event(ev):
    if ev.status_code in LOGIN_PROBLEMS:
        print('登入有問題，不要重試：', ev.message)

    可用的具名常數（實測列舉）：

    event_code : CONNECTED / DISCONNECTED / LOGIN_OK / LOGIN_FAIL / CONTRACTS_READY /
             SUBSCRIBE_OK / SUBSCRIBE_FAIL / UNSUBSCRIBE_OK / UNSUBSCRIBE_FAIL
status_code: SUCCESSFUL_OPERATION(SW000) / SW_DISCONNECTED(SW001) /
             SW_LOGIN_FAILED(SW002) / SW_SUBSCRIBE_FAILED(SW003) /
             SW_SUBSCRIBE_REJECTED(SW004) / SW_UNSUBSCRIBE_FAILED(SW005) /
             SW_SUBSCRIBE_LIMITED(SW006)

    直接比字面值（ev.status_code == 'SW001'）永遠可行，而且不會因為 常數缺漏而爆 AttributeError。具名常數只是可讀性較好。

    Manual Sample Input/Output

    Example 1：完整生命週期

    input

    def on_event(ev):
    print(repr(ev.event_code), repr(ev.status_code), ev.message)

api.SWQuote.set_event(on_event)
api.SWQuote.subscribe('2330')
api.SWQuote.subscribe('2330', odd=True)
api.SWQuote.subscribe('2317')
# ... 收行情 ...
api.SWQuote.unsubscribe('TWSE.2330')
api.SWQuote.unsubscribe_all()

    output（實際擷取）

    'connected'      'SW000'  StatusCode: SW000, Detail: Connected to StarWave market data server. (channel: SW001)
'login_ok'       'SW000'  StatusCode: SW000, Detail: Login succeeded. channel[SW001] 登入成功
'subscribe_ok'   'SW000'  StatusCode: SW000, Detail: Subscribed TWSE.2330.
'subscribe_ok'   'SW000'  StatusCode: SW000, Detail: Subscribed TWSEOdd.2330.Odd.
'subscribe_ok'   'SW000'  StatusCode: SW000, Detail: Subscribed TWSE.2317.
'unsubscribe_ok' 'SW000'  StatusCode: SW000, Detail: Unsubscribed TWSE.2330.
'unsubscribe_ok' 'SW000'  StatusCode: SW000, Detail: Unsubscribed all. Removed 2 subscription(s): TWSE.2317, TWSEOdd.2330.Odd.
'disconnected'   'SW001'  StatusCode: SW001, Detail: Disconnected from StarWave market data server.

    三件值得注意的事：

    1. connected 與 login_ok 只在第一次訂閱時出現，不是 set_event 當下—— 連線是延遲建立的（第一次 subscribe 才連）。
    2. unsubscribe_all() 只發一個 unsubscribe_ok，message 裡列出全部被移除的 label。
    3. 清空最後一筆訂閱後會自動斷線，緊接著一個 disconnected / SW001。 那是正常流程，不是錯誤。

    Example 2：斷線重連

    disconnected 可能是自己 unsubscribe_all() 造成的，也可能是真的掉線。 要重連就記住自己訂了什麼，收到 SW001 時重訂：

    import threading

WATCH = ['2330', '2317']
_reconnecting = threading.Lock()

def on_event(ev):
    if ev.status_code != 'SW001':
        return
    # 自己清空訂閱造成的斷線不要重連
    if not WATCH:
        return
    if not _reconnecting.acquire(blocking=False):
        return                      # 已經在重連了，別疊上去
    try:
        for sym in WATCH:
            api.SWQuote.subscribe(sym)
    finally:
        _reconnecting.release()

api.SWQuote.set_event(on_event)
api.SWQuote.set_cb(on_quote)
for s in WATCH:
    api.SWQuote.subscribe(s)

    事件回呼跟行情回呼一樣在背景執行緒跑，而且斷線時可能連續觸發。 上面用 acquire(blocking=False) 擋掉重入；不要在事件回呼裡 time.sleep() 很久， 那會卡住整條事件通道。

    Example 3：訂閱額度用完

    每個交易所每個通道上限 100 檔，超過會拿到 SW006：

    def on_event(ev):
    if ev.status_code == 'SW006':
        print('額度滿了，換通道：', ev.message)
        # api.SWQuote[1].subscribe(...)

    各交易所（TWSE/OTC/ES/TAIFEX/TWSEOdd/OTCOdd）各自獨立計算， 所以整股訂滿 100 不影響零股額度。需要更多請用 api.SWQuote[n] 的其他通道， 見 swquote.md。

    注意

    • set_event 與 set_cb 各自獨立，都是覆蓋式。
    • 連線是延遲建立的：set_event 之後要等第一次 subscribe 才會有 connected。
    • 判斷登入類失敗請比字面 'SW007'~'SW011'，那幾個沒有具名常數。
    • message 的 channel 名稱實測是 SW001（不是固定字串 StarWave）， 不要拿它去做字串比對。
    • 完整的行情資料欄位與 data_type 語意見 swquote-callback.md。
