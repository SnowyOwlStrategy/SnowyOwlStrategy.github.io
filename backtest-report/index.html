    商品設定與績效報告

    api.bt.config() 設定商品的交易成本、合約乘數與保證金，api.bt.generate_report() 依這些設定把跑完的策略彙整成績效報告，包含 KPI 摘要、每日績效、交易明細與互動式儀表板。

    以下範例中的 bt 即 api.bt。

    商品設定 config

    語法

    api.bt.config(name='strategy', symbol='symbol',
              tax_long=0, tax_short=0, daytrade_discount=1,
              fee=0, unit=1, margin_long=1, margin_short=1,
              lot_size='inf,0,floor,1')

    參數

    參數 型別 預設值 說明
    name str 'strategy' 策略規則名稱。多策略回測時的分組依據，也是 rp.report 的欄名
    symbol str 'symbol' 交易標的代號
    tax_long float 0 進場那筆成交的稅率，以進場價計算，與多空方向無關
    tax_short float 0 出場那筆成交的稅率，以出場價計算，與多空方向無關。台股證交稅在賣出時收取，填 tax_short=0.003，tax_long 維持 0
    daytrade_discount float 1 當沖稅率折扣。進出場在同一天時，稅率乘上此值（1＝無折扣、0.5＝減半）
    fee float 0 手續費。>= 1 為每口固定金額，< 1 為成交金額的費率
    unit int 1 合約乘數，名目金額 ＝ qty × unit × price。預設 1 以股計，下單數量就是股數；以張計時填 1000，下單數量要換算成張數；台指期填 200
    margin_long float 1 多單保證金。>= 10 為每口固定金額，< 10 為名目金額的比例（成數）
    margin_short float 1 空單保證金，規則同 margin_long
    lot_size str 'inf,0,floor,1' 比例下單（數量填 0～1）時的口數限制，格式為 '最大口數,最小口數,取整方式,幾口一取'，取整方式只接受 floor／ceil。固定數量下單不受影響

    fee 與 margin_long／margin_short 依數值大小決定計算方式：fee=500 是每口 500 元，fee=0.001425 是成交金額的 0.1425%。

    回傳

    商品設定物件，作為 generate_report() 輸入字典 {config: core} 的 key。

    config 只用於產生報告時的帳務計算，不影響回測本身。同一個跑完的 core 可以搭配另一份 config 重新產生報告，不需要重跑回測。

    交易成本的計算

    tax_long 乘的是進場價，tax_short 乘的是出場價，與多空方向無關。手續費為費率（fee < 1）時，每筆交易的成本為：

    cost = qty × unit × ( entry_price×(tax_long + fee) + exit_price×(tax_short + fee) )

    台股證交稅只在賣出時收取，所以只填 tax_short=0.003，tax_long 維持預設的 0。兩者都填時，進場與出場都會計稅。

    各類標的的設定

    標的 設定
    台股個股（以股計） fee=0.001425, tax_short=0.003（unit 用預設 1），數量填股數
    台股個股（以張計） fee=0.001425, tax_short=0.003, unit=1000，數量填張數
    台股 ETF 同上，改為 tax_short=0.001
    台股個股（當沖稅減半） 再加 daytrade_discount=0.5
    台指期 fee=500, tax_long=0.00002, tax_short=0.00002, unit=200, margin_long=0.13, margin_short=0.13
    美股 fee=0, tax_long=0, tax_short=0, unit=1 
    # 台股個股
cfg = bt.config(symbol='2330', fee=0.001425,
                tax_long=0, tax_short=0.003, daytrade_discount=0.5, unit=1000)

# 台指期（固定手續費／口，保證金為名目金額成數）
cfg = bt.config(symbol='TXF', tax_long=0.00002, tax_short=0.00002,
                fee=500, unit=200, margin_long=0.13, margin_short=0.13)

# 百分比下單，換算口數無條件捨去、無上限
cfg = bt.config(name='pct_TXF', symbol='TXF', tax_short=0.00002, fee=20, unit=200,
                margin_long=0.13, margin_short=0.13, lot_size='inf,0,floor,1')

    產生報告 generate_report

    語法

    api.bt.generate_report(core_dic, margin_call=False, capital=1000000, benchmark=None)

    參數

    參數 型別 預設值 說明
    core_dic dict — 必填。{config: core} 字典，core 須已跑完整段資料。可放多組一起比較
    margin_call bool False 是否把未實現的浮動虧損計入資金佔用，影響 rp.daily 的 invest 與 rp.report 的 Invest／MaxPosition。True 較保守，模擬保證金追繳
    capital int 1000000 起始資金。只在比例下單（數量填 0～1）時生效；固定數量下單時不參與計算，見下方「部位大小與 capital」
    benchmark dict／pd.Series None 基準指數的每日收盤價，index 為日期。提供後 rp.report 多一欄 benchmark，做買進持有比較

    回傳

    報告物件（以下稱 rp），內容見下方「產出內容」。

    範例

    兩個策略與基準指數一起產生報告：

    benchmark = df.set_index('DateTime')['收盤價'].resample('D').last().dropna()
rp = bt.generate_report({cfg1: core1, cfg2: core2},
                        margin_call=True, capital=10_000_000, benchmark=benchmark)

print(rp.report)                    # 兩個策略 + benchmark 並列
print(rp.core['pct_TXF'].report)    # 只看單一策略

    部位大小與 capital

    Condition.Global() 的數量（add_qty）依數值大小有兩種意義：填 0～1 的小數為比例下單，代表投入當下資金的比例，capital 生效；填大於等於 1 的數為固定數量，單位由 config.unit 決定（unit=1 為股數、unit=1000 為張數），capital 不參與計算。

    比例下單

    self.Condition.Global(True, 0.2, 0, self.PriceType.market_ioc, None, 'bk')
#                           ^^^ 投入當下資金池的 20%

    每筆進場時依當下的資金換算口數：

    • 進場時的資金 ＝ 起始資金 ＋ 進場時間之前已實現的損益
    • 口數 ＝ 資金 × 比例 ÷ 每口所需資金（margin），再依 lot_size 取整，並限制在最小與最大口數之間

    capital 只累加已實現損益，不扣除未平倉部位佔用的資金。多檔同時進場時，每檔都以同一份資金計算口數，比例 × 同時持有檔數大於 1 時，總部位會超過資金。多檔輪動時比例取 1/檔數，總部位不會超過資金：

    N = len(SYMS)
self.Condition.Global(True, 1 / N, 0, self.PriceType.market_ioc, None, 'bk')

    以 3 檔、capital=10,000,000、比例 1/3（unit=1000）回測的結果：

    項目 數值
    交易筆數 164（其中 2 筆口數取整為 0）
    單筆進場金額中位數 2,700,843
    單筆進場金額最大值 3,259,638
    MaxPosition 8,563,185（小於 capital）

    此時 rp.report 的 Strategy 欄是共用資金池的組合結果。

    資金 × 比例不足以買進一個單位（例如以張計時的一張台股）時，該筆口數依 floor 取整為 0。所有交易都是 0 時無法產生報告，見下方「錯誤處理」。

    固定數量下單

    數量大於等於 1 時，capital 不參與計算。同一組固定 1 口的策略，capital 設 10 萬、100 萬、1 億時，Invest、NetProfit、MaxPosition、TotalTrades、TotalReturns、AvgCashUtilizationRate 都相同，TotalReturns 為 NetProfit / Invest。

    每筆固定金額時，數量 ＝ 金額 ÷ 價格，也就是股數，搭配 unit=1。各檔依自己的訊號進出，互不影響：

    cfg = bt.config(symbol=s, fee=0.001425, tax_long=0, tax_short=0.003, unit=1)

def on_bar(self, row):
    if row['sig'] and self.global_qty == 0:
        qty = 100000 / row['Close']          # 每筆 10 萬元
        self.Condition.Global(True, qty, 0, self.PriceType.market_ioc, None, 'bk')

    以 unit=1 執行時，單筆進場金額中位數為 100,077 元。unit=1000 時數量代表張數，同一個公式算出的 100000 / 2375 = 42.1 會被當成 42.1 張（42,100 股）。以張計時，自行換算成張數並取整：

    qty = max(1, round(100000 / (row['Close'] * 1000)))    # unit=1000

    台股一張的金額常達數十萬元，10 萬元買不到一張時，max(1, ...) 會進位為一張，此寫法的單筆進場金額中位數為 653,430 元。要精準控制每筆金額時使用 unit=1。

    兩種寫法的比較

    比例（輪動） 固定金額
    數量 小於 1，為投入資金的比例 大於等於 1，為實際股數
    unit 1000 或 1 皆可 1
    capital 生效，限制總資金 不參與計算
    適用 多檔輪動、資金有限 各檔訊號獨立、評估單一規則的期望值
    查看結果 rp.report 的 Strategy 欄 各檔的欄位

    產出內容

    屬性／方法 說明
    rp.report 績效摘要（KPI），欄名見下方「rp.report 的欄」
    rp.daily 每日績效彙總（權益曲線）
    rp.trade_detail 進出場配對明細，逐筆交易與損益計算的依據
    rp.trade_main 委託／成交明細（合併視角），每筆下單都會列出，不論是否成交
    rp.position 每日持倉部位
    rp.daily_close 每日收盤價（日期 × 標的的寬表）
    rp.core[name] 單一策略獨立的結果（StrategyResult），不受其他策略影響。name 對應 config.name
    rp.dashboard() 產生互動式績效儀表板（HTML）
    rp.save(path=None) 存成一個 xlsx 檔
    rp.set_benchmark(data) 產生報告後設定或更新基準指數

    rp.report 的欄

    欄名 出現時機 內容
    Strategy 一律 所有策略的交易依時間合併、共用一份 capital 計算的結果。單策略時就是該策略的結果
    各策略的 config.name 多策略時 該策略獨占全部資金的單獨結果。各欄加總不等於 Strategy
    benchmark 有設定 benchmark 時 基準指數的買進持有績效

    單策略時只有 Strategy 欄（有 benchmark 時再加 benchmark 欄），沒有以 config.name 命名的欄：

    cfg = bt.config(name='MA20_60_2330', symbol='2330', ...)
rp = bt.generate_report({cfg: core}, benchmark=bench)
print(list(rp.report.columns))
    輸出
    ['Strategy', 'benchmark']

    同一段程式要處理單策略與多策略時，可以這樣取欄：

    COL = 'Strategy' if len(core_dic) == 1 else cfg.name
invest = rp.report.loc['Invest', COL]

    benchmark 的計算區間

    benchmark 欄的績效從策略的 StartDate（第一筆進場日）起算，與策略比較同一段期間。因此它與從資料第一天算起的買進持有報酬不同，策略的暖身期越長（例如 MA240），差距越大：

    rp.report.loc['TotalReturns', 'benchmark']     # 2.9284 ← 從 StartDate(2022-08-15) 起
bench.iloc[-1] / bench.iloc[0] - 1             # 3.0703 ← 從資料第一天(2022-08-01) 起

    rp.dashboard()

    產生互動式績效儀表板（HTML）。

    rp.dashboard(path=None, view='notebook', page_size=20, unit=1e4, unit_label='萬')
    參數 型別 預設值 說明
    path str None 存檔路徑。None 時自動命名為 YYYYMMDD_dashboard_N.html 存在目前資料夾，N 從 1 遞增，不覆蓋既有檔案
    view str 'notebook' 顯示方式。'notebook'：在 Jupyter 內嵌顯示，在 notebook 以外的環境只會印出 <IPython.core.display.HTML object>；'web'：存檔後用瀏覽器開啟；None：只存檔，不顯示也不開啟
    page_size int 20 表格每頁筆數
    unit float 1e4 金額圖的單位
    unit_label str '萬' 金額圖的單位名稱，與 unit 對應（unit=1, unit_label='元' 以元顯示）

    view='notebook'、path=None 且在 notebook 中執行時只內嵌顯示、不存檔；其餘組合都會存檔。在終端機或腳本中執行時，指定 path 以決定檔案位置：

    rp.dashboard(path='dashboard.html', view='web')     # 腳本：存檔並用瀏覽器開啟（只存檔用 view=None）
rp.dashboard()                                      # notebook

    儀表板有四個分頁：

    分頁 內容
    總覽 上方 10 張卡片（總報酬率、平均年報酬、年化報酬、投資金額、淨利潤、勝率、Calmar、Sharpe、Sortino、年化波動率）；近期報酬與交易次數、資金使用率、資料明細（含 MddRatio／MddAmount／MddDuration）；累計報酬、月報酬熱圖（% 與金額）、損益與回撤（金額）圖、最大 5 次回撤（天數／金額）表
    績效分析 個股績效表（交易次數、勝率、total_qty、報酬率、損益）、每日摘要
    交易明細 委託（最新委託／全部委託）、成交（最新庫存／全部成交）
    個股分析 選擇股票後顯示 K 線（含進出場標記，並畫出策略的 self.char／self.char1 指標）、進出場規則績效、個股委託、個股成交

    rp.report 的每一列都會出現在總覽（卡片或表格），新增的列會自動加在「資料明細」的最後。

    個股分析會把每檔每根 K 棒存進 HTML，股票池大時檔案也大：美股 6,490 檔、317 萬根 K 棒約 116 MB，產生時間約 17 秒。

    rp.save()

    把報表存成一個 xlsx 檔，回傳實際存檔的路徑。

    rp.save()                        # 存成 ./YYYYMMDD_report_N.xlsx，回傳實際路徑
rp.save('my_report.xlsx')
    sheet 內容
    report rp.report
    daily rp.daily（index 名為 date）
    trade_main rp.trade_main
    trade_detail rp.trade_detail
    symbol_stats 個股績效（同儀表板的績效分析頁）
    rule_stats 進出場規則績效（股票代號、進場規則、出場規則、次數、占比、total_pnl、average_pnl）
    • 未指定 path 時自動命名為 YYYYMMDD_report_N.xlsx 存在目前資料夾，N 從 1 起找第一個未使用的編號，不覆蓋舊檔；指定 path 時副檔名一律改為 .xlsx。
    • rp.daily_close 不存入檔案：股票池的「天數 × 檔數」寬表動輒幾十萬格，寫入 xlsx 很耗時。需要時直接使用 rp.daily_close。

    rp.set_benchmark()

    rp.set_benchmark(data)

    產生報告後設定或更新基準指數。data 為每日收盤價（dict 或 pd.Series，index 為日期），同一天有多筆時取最後一筆。

    報表欄位

    時間欄位的型別

    rp.trade_main 的 order_dt／dt 與 rp.trade_detail 的 entry_time／exit_time／current_time 是字串，不是 datetime64（dtype 在 pandas 2 顯示 object、pandas 3 顯示 str）。做日期運算（例如 .dt.month、計算持有時間）前，先用 pd.to_datetime() 轉換。空值為 NaN，可用 isna() 篩選未平倉的列。

    rp.trade_main

    委託與成交明細。

    欄位 說明
    name 策略名稱（對應 config.name）
    symbol 交易標的代號
    rule 觸發此筆委託的規則名稱（Condition.Global() 的 rule）
    type 委託類型，例如 market_ioc、limit_rod
    order_dt 委託時間
    order_qty 委託數量（正＝買、負＝賣）
    order_price 委託價格（市價單為 0）
    dt 實際成交時間
    qty 實際成交數量
    price 實際成交價格
    after_qty 成交後的持倉數量
    uid 唯一委託識別碼
    math_uid 配對用識別碼（對應進出場配對）

    rp.trade_detail

    進出場配對明細，每筆交易一列。

    欄位 說明
    name 策略名稱
    symbol 交易標的代號
    direction long（多）或 short（空）
    type 平倉（已結清）或 未平倉（仍持有）
    entry_rule／entry_time／entry_price 進場的規則、時間、價格
    exit_rule／exit_time／exit_price 出場的規則、時間、價格（未平倉為 NaN）
    current_time／current_price 未平倉時的最新時間與市價（已平倉為 NaN）
    qty 成交數量，取絕對值。單位依 unit 而定（unit=1 為股數、unit=1000 為張數）
    unit 合約乘數
    cost 總交易成本（手續費 ＋ 交易稅）
    entry_amount 進場時實際佔用的資金（含保證金），為負值
    exit_amount 出場後回收的金額，等於進場佔用的資金加上 pnl。未平倉為 NaN，改看 predict
    predict 未平倉部位以當前市價估算的出場金額
    pnl 本筆損益，已扣除 cost
    return 本筆報酬率（pnl / abs(entry_amount)）
    margin 每口的保證金佔用

    扣除成本前的毛損益為 (pnl + cost).sum()。進出頻繁的策略，毛損益可能接近零、虧損幾乎都來自成本，建議先比較毛損益與成本，再看報酬率。

    rp.daily

    以交易日為單位追蹤資產變化。最大回撤與波動率都以 value_pct 計算。

    欄位 說明
    cashflow 當日現金流（進出場產生的淨現金變化）
    entry_cost 當日持倉的進場成本（負值，代表佔用資金）
    market_value 當日持倉的浮動市值
    profit_loss 累計損益（已實現 ＋ 未實現）
    unrealized 未實現損益（entry_cost + market_value）
    realized 已實現損益（profit_loss - unrealized）
    position 當日最大資金佔用（以保證金或進場金額估算）
    invest 累計最大投入資本，為報酬率的分母，取歷史最大值。是否計入未實現虧損由 margin_call 決定
    dd 當日回撤金額，等於 profit_loss - profit_loss.cummax()（創新高當天為 0）。rp.report 的 MddAmount 是它的最小值
    PNL/COST 累計損益 ÷ 累計進場成本
    return 當日報酬：累計報酬率（profit_loss / invest）的逐日差分
    return_pct 當日報酬率：(1 ＋ 當日累計報酬率) ÷ (1 ＋ 前一日累計報酬率) − 1
    value_pct 當日資產變動率：profit_loss.diff() / (前日 profit_loss + invest)，風險指標都以此計算

    rp.report（KPI）

    rp.report 共 28 項 KPI，各列定義如下：

    欄位 說明
    StartDate 第一筆進場日期
    EndDate 回測結束日期
    BacktestDate 執行回測當天的日期
    TotalReturns 累計總報酬（daily['return'].sum()）
    CAGR 年化報酬率（複利）
    AAR 年化報酬率（單利：平均每日報酬 × 252）
    MddRatio 最大回撤比率（以 value_pct 計算，負數）
    MddAmount 最大回撤金額，等於 daily['dd'].min()（負數，元）。月中跌深、月底反彈時月損益不會反映這段回撤，因此可能大於任何單月的虧損
    MddDuration 最長回撤持續天數
    CalmarRatio CAGR / abs(MddRatio)，也是 bt.Tools.optimize() 的評分
    SharpeRatio 夏普比率（以 value_pct 計算，年化）
    SortinoRatio 索提諾比率（只計下行波動）
    AnnualisedVolatility 年化波動率（value_pct 標準差 × √252）
    WinRate 勝率（已平倉交易中 pnl > 0 的比例）
    ProfitLossRatio 盈虧比（獲利總額 ÷ 虧損總額）
    MaxPosition 期間最大資金佔用（position 的峰值）
    Invest 期間最大投入資本（invest 的峰值，受 margin_call 影響）
    AvgCashUtilizationRate 平均資金使用率
    TotalTrades 總交易筆數（含未平倉）
    ProfitTimes／LossTimes 獲利／虧損筆數（已平倉）
    NetProfit 淨利，等於 round(daily['profit_loss'].iloc[-1])
    TradeCost 總交易成本（所有手續費與稅）
    AvgProfitPerTrade NetProfit / TotalTrades
    WeeklyReturn 近 5 根（約 1 週）報酬
    MonthlyReturn 近 20 根（約 1 月）報酬
    QuarterlyReturn 近 60 根（約 1 季）報酬
    AnnualReturn 近 240 根（約 1 年）報酬

    NetProfit 取自每日權益曲線的末值並四捨五入。期末有未平倉部位時，與 rp.trade_detail['pnl'].sum() 會有小差異：未平倉部位在 trade_detail 預先扣除進出場雙邊成本，在 daily 只計單邊。全部平倉時兩者一致。

    設定 benchmark 時多一欄 benchmark；WinRate、TotalTrades 等交易統計不適用於基準指數，值為空。

    曝險率

    28 項 KPI 不包含曝險率（有部位的交易日占比），可從 rp.daily 計算：

    exposure = (rp.daily['position'].abs() > 0).mean()     # 有部位的交易日佔比

    比較策略與買進持有時，可用曝險率判斷落差的來源。標的大漲期間，空手的每一天都是機會成本；曝險率低、報酬又低於買進持有時，落差來自持有時間，屬於策略結構的差異，調整參數無法改善。

    錯誤處理

    錯誤訊息 原因 處理方式
    RuntimeError: make_daily: 每日損益全為 0，無法產生報表。
    常見原因是 pandas / numpy 版本不相容導致索引對不起來，...    		 所有交易的口數都是 0。最常見的情況是比例下單時，資金 × 比例不足以買進一個單位（例如台股一張 1000 股），口數依 floor 取整為 0 提高 capital、減少檔數，或改用 unit=1 以股計
    KeyError: 'MA20_60_2330' 單策略時 rp.report 只有 Strategy 欄，以 config.name 取欄會找不到 單策略以 'Strategy' 取值，見上方「rp.report 的欄」
