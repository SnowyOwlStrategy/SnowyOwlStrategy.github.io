    配方集：實跑驗證過的寫法範例

    所屬章節：入門 每一份都實跑驗證過，教一種寫法；照使用者的規格組合，不要整份照抄 範例只示範寫法，參數不是建議值，也不附績效數字；程式都在 2026-10-21 實跑過

    這頁在解決什麼

    寫一支最簡單的單檔回測，資訊散在六頁裡：

    backtest.md          → daily_bars() 範本、為什麼不用 get_stock_ohlc
backtest-strategy.md → 標準骨架、on_init 放參數、暖身期
backtest-order.md    → Condition.Global 七個參數
backtest-report.md   → unit/capital/tax 陷阱
backtest-tools.md    → self.Ind 每根都要呼叫
data-history.md      → 各頻率歷史長度

    這頁把它們拼好。 要改需求時再回去查對應那頁。

    共用前置

    import sys
sys.path.insert(0, r'<snowyowl_project 路徑>')    # 用原始碼樹時才需要；pip 裝的不用
import pandas as pd
import snowyowl as so

api = so.login(type='google')        # 或 so.login('user@x.com', 'pwd')

    取日 K 的標準函式

    日 K 一律從 api.MSMP 取，不要用 bt.Tools.get_stock_ohlc—— 後者是 1 分 K resample，跟積木的日頻 sig 對不上，還多一次大量下載。

    def daily_bars(api, symbol, adj=True):
    """回傳可直接餵 feed_data 的 df。adj=True 用還原價。"""
    k = api.MSMP.日_K
    p = 'adj_' if adj else ''
    cols = {'開盤價': f'{p}Open', '最高價': f'{p}High', '最低價': f'{p}Low',
            '收盤價': f'{p}Close', '成交量': f'{p}Volume' if adj else 'Volume'}
    df = pd.DataFrame({zh: getattr(k, en)[symbol] for zh, en in cols.items()})
    df.index.name = 'DateTime'
    return df.dropna().reset_index()      # ← dropna 必要，未上市期間是 NaN

    要 adjclose 就整組都用 adj_*（含 adj_Volume），不要混用還原價與未還原量。

    配方一：單檔技術指標回測（每次固定金額）

    範例：2330 還原價 MA20 在 MA60 之上就買、跌回之下就賣，每次買 20 萬元。 重點：每次固定金額 → qty = 金額 / 價格（股數）搭 unit=1；指標寫進 self.char 才會畫在 K 線上。

    SYM, AMOUNT = '2330', 200_000
df = daily_bars(api, SYM, adj=True)

class MaCross(bt.Core):
    def on_init(self):                      # 只放參數與狀態，下單會 RuntimeError
        self.n_fast, self.n_slow = 20, 60
        self.amount = AMOUNT
        self.close_list = []

    def on_bar(self, row):
        self.close_list.append(row['Close'])         # row 的 key 一律英文
        fast = self.Ind.rolling_mean(self.close_list, self.n_fast)
        slow = self.Ind.rolling_mean(self.close_list, self.n_slow)
        self.char['ma20'], self.char['ma60'] = fast[-1], slow[-1]   # 進 char 才上圖
        if len(self.close_list) < self.n_slow:
            return                                   # 暖身期不下單

        if fast[-1] > slow[-1] and self.global_qty == 0:
            qty = self.amount / row['Close']         # ★ 股數，必須搭 unit=1
            self.Condition.Global(True, qty, 0, self.PriceType.market_ioc, None, 'bk')
        elif fast[-1] < slow[-1] and self.global_qty > 0:
            self.Condition.Global(True, -self.global_qty, 0,
                                  self.PriceType.market_ioc, None, 'bp')

core = MaCross()
core.feed_data(df, ['DateTime', '開盤價', '最高價', '最低價', '收盤價', '成交量'])

cfg = bt.config(name='MA20_60_2330', symbol=SYM,
                fee=0.001425, tax_long=0, tax_short=0.003, unit=1)   # 個股稅率（ETF 用 0.001）
bench = df.set_index('DateTime')['收盤價']                           # buy&hold 對照
rp = bt.generate_report({cfg: core}, capital=1_000_000, benchmark=bench)
rp.dashboard(path='dashboard_ma.html', view='web')      # ★ 腳本裡要給 path；'web' = 存檔並開瀏覽器

    單策略時報表欄名是 Strategy（有 benchmark 就多一欄 benchmark），不是 config.name： rp.report['Strategy']。

    配方二：積木訊號當進出場

    積木選出的 sig 是日頻矩陣，與 MSMP 日 K 天然對齊，不需 reindex/ffill。

    SYM = '2330'
con = api.Block.con_tw('今日收盤價<>D日(周月)均線', period=20, table='日_K')
r = api.Block.screener_tw([con])

df = daily_bars(api, SYM, adj=True)
df['sig'] = df['DateTime'].map(r['sig'][SYM]).fillna(False)

class BlockStrategy(bt.Core):
    def on_bar(self, row):
        if row['sig'] and self.global_qty == 0:
            self.Condition.Global(True, 1, 0, self.PriceType.market_ioc, None, 'bk')
        elif not row['sig'] and self.global_qty > 0:
            self.Condition.Global(True, -self.global_qty, 0,
                                  self.PriceType.market_ioc, None, 'bp')

core = BlockStrategy()
core.feed_data(df, ['DateTime', '開盤價', '最高價', '最低價', '收盤價', '成交量'],
               columns=['sig'])        # ★ 額外欄位一定要宣告，否則 row 裡沒有
cfg = bt.config(name=f'block_{SYM}', symbol=SYM,
                fee=0.001425, tax_long=0, tax_short=0.003, unit=1000)
rp = bt.generate_report({cfg: core}, capital=1_000_000)
rp.dashboard(path='dashboard_block.html', view='web')

    選股結果不要直接當回測標的 —— 用今天選出的股票回測過去是 look-ahead， 等於事先知道誰會被選上。要嘛用固定清單，要嘛在策略內逐日重算。

    配方三：多檔組合（共用資金池）

    關鍵：qty 要填 0~1 的比例，capital 才會生效。固定口數走向量化路徑，capital 完全不參與計算。

    SYMS = ['2330', '2317', '2454', '1301', '2882']
W = 1 / len(SYMS)                     # ★ 1/檔數 是安全上限，見下方說明

class PctStrategy(bt.Core):
    def on_init(self):
        self.n_fast, self.n_slow = 5, 20
        self.close_list = []

    def on_bar(self, row):
        self.close_list.append(row['Close'])
        fast = self.Ind.rolling_mean(self.close_list, self.n_fast)
        slow = self.Ind.rolling_mean(self.close_list, self.n_slow)
        if len(self.close_list) < self.n_slow:
            return
        if fast[-1] > slow[-1] and self.global_qty == 0:
            self.Condition.Global(True, W, 0, self.PriceType.market_ioc, None, 'bk')
        elif fast[-1] < slow[-1] and self.global_qty > 0:
            self.Condition.Global(True, -self.global_qty, 0,
                                  self.PriceType.market_ioc, None, 'bp')

core_dic = {}
for s in SYMS:
    c = PctStrategy()
    c.feed_data(daily_bars(api, s), ['DateTime','開盤價','最高價','最低價','收盤價','成交量'])
    core_dic[bt.config(name=s, symbol=s, fee=0.001425,
                       tax_long=0, tax_short=0.003, unit=1000)] = c

rp = bt.generate_report(core_dic, capital=10_000_000)
print(rp.report['Strategy'])          # ★ 只有這一欄是組合，其餘是「該檔獨佔全部資金」
rp.dashboard(path='dashboard_portfolio.html', view='web')

    rp.report 逐檔加總 ≠ Strategy。 其餘各欄是單獨視角。

    為什麼是 1/檔數：capital 只累加已實現損益、不扣未平倉佔用的資金， 所以 N 檔同時進場時每檔都拿同一份 capital 的比例算口數， weight × 同時持有檔數 > 1 就是隱性槓桿。

    資金不夠時的誤導訊息：capital × weight 買不起一張（台股 1000 股）時， floor 把口數夾成 0，全部被夾掉會拋 RuntimeError: make_daily: 每日損益全為 0——訊息說是版本問題， 實際上幾乎都是資金不夠。三種解法：提高 capital、減少檔數， 或改用零股 unit=1（檔數多、資金小時這才是正解，見配方五）。

    配方四：期貨雙均線多空反手（台指期 TXF）

    範例：30 分 K、MA10 上穿 MA30 做多、下穿做空、多空反手、結算日強制出場。 回測用的期貨 1 分 K 在 api.MSMP._fut_TXF（底線私有屬性）。 期貨沒有積木（積木的資料是台股個股矩陣），進出場條件寫在 on_bar。

    import numpy as np

df1 = api.MSMP._fut_TXF     # DateTime, Open, High, Low, Close, TotalVolume, settlement

class DualMA(bt.Core):
    def on_init(self):
        self.n_fast, self.n_slow = 10, 30
        self.tick_map = [(np.inf, 1)]        # ★ 期貨最小跳動 1 點，不設會套股票規格
        self.C = []

    def on_bar(self, row):
        self.C.append(row['Close'])
        fast = self.Ind.rolling_mean(self.C, self.n_fast)
        slow = self.Ind.rolling_mean(self.C, self.n_slow)
        if len(self.C) <= self.n_slow:
            return                            # 暖身期不下單
        self.char['fast'], self.char['slow'] = fast[-1], slow[-1]
        mkt = self.PriceType.market_ioc

        # 結算棒：用當根收盤強制平倉，這根不再開新倉
        if row['DateTime'] == row['Settlement']:
            self.Condition.Global(self.global_qty != 0, -self.global_qty, row['Close'],
                                  self.PriceType.compel_now, False, '結算')
            return

        # ★ 「上穿」要比較前一根，不是單純比大小
        cross_up = fast[-2] <= slow[-2] and fast[-1] > slow[-1]
        cross_dn = fast[-2] >= slow[-2] and fast[-1] < slow[-1]

        # ★ 多空反手拆兩張：先平舊倉（net），再開新倉（bk / sk）
        g = self.global_qty
        if cross_up and g <= 0:
            if g < 0:
                self.Condition.Global(True, -g, 0, mkt, None, 'net')
            self.Condition.Global(True, 1, 0, mkt, None, 'bk')
        elif cross_dn and g >= 0:
            if g > 0:
                self.Condition.Global(True, -g, 0, mkt, None, 'net')
            self.Condition.Global(True, -1, 0, mkt, None, 'sk')

core = DualMA()
core.set_tick_period(freq=30, need_settlement=True,      # 30 分 K，日盤+夜盤
                     args=['DateTime','Open','High','Low','Close','TotalVolume'])
core.feed_tick_df(df1)                        # ★ 期貨走 feed_tick_df，不是 feed_data
cfg = bt.config(name='dualma', symbol='TXF', fee=500,
                tax_long=0.00002, tax_short=0.00002, unit=200)
rp = bt.generate_report({cfg: core})
rp.dashboard(path='dashboard_txf.html', view='web')

    多空反手：一張單或兩張單

    兩種寫法都能反手，2026-10-21 用上面這組參數實跑對照：

    寫法 交易筆數、損益、多空拆分 trade_detail['exit_rule']
    拆兩張（上面的寫法） 完全相同 舊倉出場標成 net、結算標成 結算
    一張補齊：Global(cross_up and g < 1, -g + 1, ...) 完全相同 舊倉出場被標成新倉的規則名（bk／sk）

    所以只看總損益兩種都可以；要看「進出場規則績效」（儀表板、rp.save() 的規則分頁）就拆兩張。 部位檢查要用 <= 0／>= 0（或一張寫法的 < 1／> -1），不是 == 0——用 == 0 就只能空手時進場，反不了手。

    多空要分開看損益時：

    td = rp.trade_detail
for d in ('long', 'short'):
    s = td[td['direction'] == d]
    print(f'{d}: {len(s)} 筆, pnl {s["pnl"].sum():,.0f}, 勝率 {(s["pnl"]>0).mean()*100:.1f}%')

    期貨四個必做：tick_map=[(np.inf,1)]、fee=500（>=1 自動切換成每口固定金額）、 unit=200、結算日判斷用 row['DateTime'] == row['Settlement']。

    要多週期（30 分進場 + 日線過濾）一定要走 set_tick_period(freq=[30,'D']) + feed_tick_df， feed_data 不會觸發 on_bar2。

    配方五：目標權重輪動（選股 + 定期換股）

    範例：季報 ROE 最高的 10 檔，每次季報公告日換股，每檔 1/10，只買股價 ≥ 20 元、20 日均成交額前 50% 的股票。 重點：輪動用 qty = 1/N（百分比路徑）；小資金做多檔輪動一定要用零股，見下方對照。

    TOP_N, CAPITAL = 10, 1_000_000
M = api.MSMP

# ── 1) 股池：排除 ETF / KY / DR ─────────────────────────
bad = set(M.list['etf']) | set(M.list['KY']) | set(M.list['DR'])
close     = pd.DataFrame(M.日_K.adj_Close)
raw_close = pd.DataFrame(M.日_K.Close)      # ★ 未還原價才是真實股價，門檻用它
vol       = pd.DataFrame(M.日_K.Volume)     # 單位是「張」
univ = [c for c in close.columns if c not in bad]
close, raw_close, vol = close[univ], raw_close[univ], vol[univ]
R = close.index

# ── 2) 可交易性遮罩（排名前先套）────────────────────────
turnover = (raw_close * vol * 1000).rolling(20).mean()     # ★ Volume 是張，要 ×1000
tradable = (turnover.rank(axis=1, pct=True) > 0.5) & (raw_close >= 20)

# ── 3) 因子：季報 ROE，用官方方法轉成公告日 ──────────────
roe = M.季財報_財務指標.ROE_稅後權益報酬率
feat = pd.DataFrame(roe.index_str_to_date()).reindex(columns=univ)
feat = feat.reindex(feat.index.union(R)).ffill().reindex(R)   # union→ffill→reindex

# ── 4) 換股日 = 季報公告日，每次選 top_n ─────────────────
pub = pd.DataFrame(roe.index_str_to_date()).index
score = feat.where(tradable)                  # ★ 先遮罩再排名，母體才一致
picks = {d: score.loc[d].dropna().nlargest(TOP_N).index.tolist()
         for d in sorted(set(pub) & set(R)) if score.loc[d].notna().any()}

# ── 5) 攤成「每天該持有誰」的布林表 ──────────────────────
all_syms = sorted({s for v in picks.values() for s in v})
hold = pd.DataFrame(False, index=R, columns=all_syms)
cur = []
for d in R:
    if d in picks:
        cur = picks[d]
    if cur:
        hold.loc[d, [c for c in cur if c in hold.columns]] = True

# ── 6) 每檔一個 core，qty=1/N 走百分比路徑 ───────────────
W = 1 / TOP_N

class Rotate(bt.Core):
    def on_bar(self, row):
        if row['sig'] and self.global_qty == 0:
            self.Condition.Global(True, W, 0, self.PriceType.market_ioc, None, 'bk')
        elif not row['sig'] and self.global_qty > 0:
            self.Condition.Global(True, -self.global_qty, 0,
                                  self.PriceType.market_ioc, None, 'bp')

    零股 vs 整股：小資金只能做零股

    unit=1 是以股計價，也就是零股。這不是變通寫法—— 小資金做多檔輪動在現實中本來就是買零股。實測對照（另一組設定：capital 100 萬、20 檔、W=1/20）：

    設定 結果
    unit=1（零股） 正常跑。單筆進場中位 53,031 元（≈ capital/20）、股數中位 1560 股、最小 120 股
    lot_size='inf,0,floor,1000'（整股） 掛掉，全期只成交 2 筆

    整股版之所以掛掉：capital × 1/20 = 5 萬，買不起一張台股（動輒幾十萬）， floor 把口數夾成 0，然後拋出那個會誤導人的錯誤訊息：

    RuntimeError: make_daily: 每日損益全為 0，無法產生報表。
常見原因是 pandas / numpy 版本不相容…

    它跟版本無關，就是資金不夠買一個單位。

    你要的 設法
    零股（1 股一取） unit=1，lot_size 用預設 'inf,0,floor,1'
    整股（1000 股一取） unit=1 + lot_size='inf,0,floor,1000'，且 capital × W 要買得起一張
    整張思考（qty 是張數） unit=1000，qty 自己換算成張數

    配方六：訊號驗證（IC 與分組單調性）

    在花時間跑回測之前先做這個。

    兩個一定要知道的陷阱

    ① 月頻／季頻的 index 是字串，用 index_str_to_date() 轉，不要自己接。

    月_營收 的 index 是 '2026-M08'（營收所屬月份），不是公告日。 直接拿去跟日頻對齊就是未來函數——8 月營收要到 9/10 才公告。 MSMP 的矩陣有現成方法：

    rev = api.MSMP.月_營收.YoY          # index: '2026-M06', '2026-M07', '2026-M08'
rev_d = rev.index_str_to_date()     # index: 2026-07-13, 2026-08-10, 2026-09-10

    它做了三件事，自己接 INDEX['M'] 都做不到：

    做了什麼 說明
    月頻 → 次月 10 日 月營收法定公告日；12 月跨年處理好；再用 _to_trading_day() 順延到實際交易日（2026-M06 → 07-13 因為 7/10 是週末）
    季頻 → 財報公告日 Q1→5/15、Q2→8/14、Q3→11/14、Q4→次年 3/21。2025-Q4 → 2026-03-23
    自動遮蔽下市後的資料 依 delist_dates，下市後布林填 False、數值填 NaN。這是防倖存者偏差的關鍵

    年頻（'2026-Y'）同樣支援。一律用它，不要自己拼日期。

    ② corrwith 會炸，要先 pd.DataFrame() 脫殼。

    MSMP 回的是 ProboDataFrame（pd.DataFrame 的子類），它覆寫了 __mul__ / __sub__ 等運算子去做自動 reshape。pandas 的 corrwith 內部會做 ldem * rdem， 一旦兩邊 index 型態不同就會走進 reshape 然後爆掉：

    TypeError: '<=' not supported between instances of 'str' and 'Timestamp'

    解法是脫殼成純 pandas：

    close = pd.DataFrame(api.MSMP.日_K.adj_Close)     # ← 加這層就好

    一般的矩陣運算（相加、相除、比大小）要保留 ProboDataFrame， 自動對齊很好用。只有在呼叫 corrwith 這類 pandas 內建統計方法時才需要脫殼。

    完整程式碼

    import pandas as pd

close = pd.DataFrame(api.MSMP.日_K.adj_Close)     # ★ 脫殼
fwd = close.shift(-20) / close - 1                # 未來 20 日報酬
R = close.index

# 特徵：季報營業利益率，轉成公告日後對齊到日頻
feat = pd.DataFrame(api.MSMP.季財報_財務指標.營業利益率.index_str_to_date())
feat = feat.reindex(feat.index.union(R)).ffill().reindex(R)   # ★ union→ffill→reindex

# ① IC
ic = feat.corrwith(fwd, axis=1).dropna()
print(f'IC n={len(ic)}, mean={ic.mean():.4f}, IR={ic.mean()/ic.std():.3f}')

# ② 分組單調性（5 組）
q = feat.rank(axis=1, pct=True)
for i in range(5):
    mask = (q > i/5) & (q <= (i+1)/5)
    print(f'  Q{i+1}: {fwd.where(mask).stack().mean()*100:+.2f}%')

    判讀標準：|IC| > 0.03 算有訊號；分組要單調才可信。 兩個都不過就別跑回測了，先換因子或做極端值處理。

    三個警告：

    1. 每次呼叫都要建新的 core——core 有狀態，重用會累積前一次的部位。
    2. 評分是 CalmarRatio（CAGR / abs(MddRatio)），完全不看交易次數—— 可能挑出只交易 3 次剛好都對的參數。
    3. 尋優本身就是過度配適的來源。 至少把資料切前後兩段分別驗。

    前後兩段分別驗

    文件到處都說「至少切前後兩段」，做法是這樣：

    td = rp.trade_detail
d = pd.to_datetime(td['entry_time'])        # ★ 時間欄是字串，要先轉
mid = d.min() + (d.max() - d.min()) / 2

for label, mask in (('前段', d < mid), ('後段', d >= mid)):
    s = td[mask]
    print(f'{label}: {len(s)} 筆, pnl {s["pnl"].sum():,.0f}, '
          f'勝率 {(s["pnl"]>0).mean()*100:.1f}%')

    兩段差距很大（例如獲利幾乎全來自其中一段）時，代表參數吃的是某段特定行情，不是穩定的邊際優勢。

    entry_time / exit_time 都是 strftime 過的字串不是 datetime64， 直接用 .dt 會失敗，一定要先 pd.to_datetime()。

    更嚴格的做法是只在前段尋優、拿後段驗證（真正的樣本外）：

    # 只餵前段資料尋優 → 得到 best → 用 best 跑後段，看還成不成立

    分段驗證不過的參數，optimize 給的分數再漂亮都不能用。

    配方八：多因子輪動的寫法（分步）

    2026-10-21 實跑驗證（so.login 正式帳號）。 這份不是可以直接貼上執行的腳本，而是多因子輪動每一步的關鍵寫法。 照使用者的規格（哪些因子、哪幾層過濾、何時換股、部位怎麼給）把各步組起來； 登入、報表、benchmark、儀表板的寫法同配方五。

    適用的規格長這樣：多個財報／營收因子用 percentile 排名合成分數、排名前先套可交易性過濾、 依公告日換股、每檔固定權重。

    規格 → 寫法對照（先對應積木，做不到才手寫並標明）

    規格類型 寫法 為什麼
    價格門檻（股價 ≥ X 元） 積木 a1：left='日_K.Close'（未還原）>= X 門檻一律用未還原價
    流動性地板（衝擊成本） 積木 a1：left='日_K.成交額_百萬'、left_rolling=20、left_agg='mean'、>= capital×max_w/衝擊比例/1e6 成交額_百萬 本身就是未還原的實際成交金額，單位百萬
    百分比排名過濾（前 X%） 手寫 rank(axis=1, pct=True) > 1 - X 積木的 rank 只能取「前 N 名」，不能取百分比
    財報／營收因子 index_str_to_date() → union → ffill → reindex 月營收要到次月 10 日、季報要到公告日才知道；也自動遮蔽下市股
    換股日 各頻率公告日 union，to_period('M') 分組取 max 「同月取最新」
    每檔 1/N qty = 1/TOP_N（< 1 走百分比路徑），unit=1 零股 100 萬 / 20 檔 = 5 萬，買不起整張

    步驟 1：股池與日期軸

raw_close, vol = pd.DataFrame(k.Close), pd.DataFrame(k.Volume)   # 未還原價、量(張)

    步驟 2：可交易性遮罩（積木做得到的用積木）

    b1 = B.con_tw(id='a1', left='日_K.Close', operator='>=', const=價格門檻)

    百分比排名積木做不到，手寫，並在程式註解標明原因。成交額用未還原 Close，Volume 是張要 ×1000：

tradable = block_ok & (turnover20.rank(axis=1, pct=True) > 0.4)        # 前 60%

    步驟 3：因子對齊到日頻

    月／季資料的 index 是 '2024-03'、'2024-Q1' 這種字串，先轉成公告日，再 union → ffill → reindex。 直接 reindex(R) 會因為日期對不上而全變 NaN；先 ffill 再 reindex 才會把公告後的值延續到每天。

    def to_daily(tbl, col):
    s = pd.DataFrame(getattr(getattr(M, tbl), col).index_str_to_date()).reindex(columns=univ)
    return s.reindex(s.index.union(R)).ffill().reindex(R)

    表名與欄名照 msmp-tables.md 一字不差（例如 季財報_財務指標 底下的欄位），不要憑印象拼。

    步驟 4：percentile 合成分數

    先套遮罩再排名（排名母體才是可交易的股票），反向因子用 1 - p，缺值填 0.5（中性），等權平均：

    p = to_daily(tbl, col).where(tradable).rank(axis=1, pct=True)
if 反向:
    p = 1.0 - p
score = p.fillna(0.5) if score is None else score + p.fillna(0.5)
# 迴圈跑完所有因子後
score = (score / 因子數).where(tradable)

    步驟 5：換股日與名單

    公告日從資料本身取：月頻取月營收任一欄、季頻取季財報任一欄的 index_str_to_date() index（下例只是借欄位拿日期）。

    pub = pd.DatetimeIndex(
    pd.DataFrame(M.月_營收.YoY.index_str_to_date()).index.union(
    pd.DataFrame(M.季財報_財務指標.營業利益率.index_str_to_date()).index))
pub = pub[(pub >= R[0]) & (pub <= R[-1])]
rebal = [d for d in pd.Series(pub, index=pub.to_period('M')).groupby(level=0).max() if d in R]
picks = {d: score.loc[d].dropna().nlargest(TOP_N).index.tolist()
         for d in rebal if score.loc[d].notna().any()}

    換股日之間名單不變，展開成「日 × 股票」的持有表，回測時當 sig 餵進去：

hold = pd.DataFrame(False, index=R, columns=all_syms)
cur = []
for d in R:
    cur = picks.get(d, cur)
    if cur:
        hold.loc[d, cur] = True

    步驟 6：回測的下單邏輯

    「新進名單買 1/N、不在名單全賣、續留不調」：

    class Rotate(bt.Core):
    def on_bar(self, row):
        self.Condition.Global(row['sig'] and self.global_qty == 0, 1 / TOP_N, 0,
                              self.PriceType.market_ioc, None, 'bk')
        self.Condition.Global((not row['sig']) and self.global_qty > 0, -self.global_qty, 0,
                              self.PriceType.market_ioc, None, 'bp')

    每檔一個 Core，餵還原價（adj_Open…adj_Volume），sig 欄由 hold[s] map 過去； bt.config(..., unit=1) 走零股。五個矩陣要在迴圈前先存成 DataFrame（寫法見配方五的 bars）： 每存取一次 k.adj_Open 這類屬性就發一次 HTTP 請求，逐檔在迴圈裡取會很慢甚至逾時。 組成 core_dic 後的報表、benchmark、儀表板同配方五。

    這類策略的常見限制

    1. 回測期間：資料長度不是固定值（見 data-history.md），rp.report 的 StartDate／EndDate 就是實際期間。 期間短、換股次數少（例如 2 年、二十幾次）不足以證明策略有效。
    2. 兩種成交額：衝擊成本地板用 成交額_百萬（交易所成交金額）；百分比排名若照規格用 Close × Volume × 1000， 兩者意義相同（都是未還原），數字不完全一樣。
    3. 現金流量表因子的正負號：例如 無形資產_增加_減少_CFI，買進記為負數。 rank 由小到大，負得最多（買最多）的排名最低，取「反向」1 - p 後分數反而最高——等於獎勵無形資產支出多的公司。 要懲罰支出就用正向。交付時用一句話說明這個方向。

    這份配方踩過的坑

    坑 症狀 正解
    積木想做「前 60%」 rank 參數只吃整數 N 百分比排名手寫 rank(pct=True)，並在程式註解標明「積木做不到」
    財報直接 reindex(R) 因子幾乎全是 NaN 先 index_str_to_date()，再 union → ffill → reindex
    先排名再套遮罩 排名母體含不可交易股，分數偏移 where(tradable) 在 rank 之前
