    撰寫策略

    策略是繼承 api.bt.Core 的類別。引擎逐根 K 棒呼叫策略的事件方法（on_bar 等），策略在事件中讀取行情與持倉、送出委託，引擎負責撮合與記帳。 事件的執行順序決定委託何時成交，撰寫策略前建議先了解本頁的執行順序。

    以下範例中的 bt 即 api.bt。

    策略骨架

    import numpy as np
import snowyowl as so

api = so.login('user@x.com', 'pwd')
bt = api.bt

df = bt.Tools.get_stock_ohlc('2330', freq=60, adj=False)


class MyStrategy(bt.Core):
    def on_init(self):
        # 1) 參數：要用 optimize 搜尋的參數放這裡，命名為 self.xxx
        self.n_fast, self.n_slow = 5, 20
        self.stl, self.pft = 1.0, 2.0
        # 2) 狀態容器
        self.close_list = []
        # 3) 期貨要改最小跳動單位（預設是股票規格）
        # self.tick_map = [(np.inf, 1)]

    def my_indicators(self, row):
        self.close_list.append(row['Close'])
        fast = self.Ind.rolling_mean(self.close_list, self.n_fast)
        slow = self.Ind.rolling_mean(self.close_list, self.n_slow)
        self.char['fast'] = fast[-1]          # 存進 char 會畫在 show_monitor 與 dashboard 的 K 線
        self.char['slow'] = slow[-1]
        if len(self.close_list) < self.n_slow:
            return False, False               # 暖身期不下單
        return fast[-1] > slow[-1], fast[-1] < slow[-1]

    def on_bar(self, row):
        long_sig, short_sig = self.my_indicators(row)

        self.Condition.Global(long_sig and self.global_qty == 0,
                              1, 0, self.PriceType.market_ioc, None, 'bk')
        self.Condition.Global(short_sig and self.global_qty > 0,
                              -self.global_qty, 0, self.PriceType.market_ioc, None, 'bp')

        # 停損停利：每根 K 棒都呼叫，不放在 if 內
        self.Condition.set_STL('bk', self.stl)
        self.Condition.set_PFT('bk', self.pft)


core = MyStrategy()
core.feed_data(df)
cfg = bt.config(symbol='2330', fee=0.001425, tax_long=0, tax_short=0.003, unit=1000)
rp = bt.generate_report({cfg: core})
print(rp.report)

    事件方法

    在子類別中覆寫需要的事件方法，未覆寫的事件不會執行。

    方法 觸發時機 用途
    on_init(self) 策略建立時呼叫一次 初始化參數與狀態。這時還沒有 K 棒，不能下單
    on_bar(self, row) 主商品 base 週期（freq[0]）的 K 棒收盤時 主要的下單邏輯。row 是當根已收盤 K 棒的 dict，等同 self.row_list[-1]
    on_bar2(self, row) 主商品第 2 週期（freq[1]）收盤時 純訊號，不觸發撮合。通常計算高週期指標存成 self.xxx，下單仍寫在 on_bar。第 3 個週期為 on_bar3，依此類推
    on_intrabar(self, row) K 棒收盤前、盤中價格變動時（每筆 tick 一次） row 是正在形成、尚未收盤的 K 棒
    on_position(self, P) 倉位變動時：開倉、加倉、部分平倉 P 是持倉物件（Position）。常見用法是以 match_uid=P.uid 為每筆持倉掛專屬出場單。完全平倉時不觸發
    on_other(self, row) 對標商品 base 週期收盤時 純訊號。多週期時依序為 on_other2、on_other3

    on_bar2／on_bar3／on_other* 只在使用 set_tick_period() ＋ feed_tick_df() 餵資料時觸發；feed_data() 不經過週期聚合，只觸發 on_bar、on_intrabar、on_position。見 資料與週期。

    Condition.Global() 只能在 on_bar、on_intrabar、on_position 中呼叫。在 on_init 中下單會產生 RuntimeError，見下方「錯誤處理」。

    一根 K 棒內的執行順序

    引擎處理每根 K 棒的順序固定如下：

    1. 更新未實現損益        （重算 global_unrealized_point、每筆持倉的 max_earn / max_loss）
2. 撮合既有委託          （用這一根的 OHLC 判斷前一根送出的委託是否成交）
      └─ 有成交 → 觸發 on_position
3. on_bar(row)           （策略的下單邏輯；這裡送出的委託在下一根才撮合）
4. 依 Condition.Global 的呼叫順序排定委託優先序
5. on_intrabar(row)

    以三根日 K、在第 0 根送出市價買單為例，事件的觸發順序為：

    on_bar(index=0)
→ on_intrabar(index=0)
→ on_position(rule=bk, index=1)      ← 在 index 1 的開盤價成交
→ on_bar(index=1)
→ on_intrabar(index=1)
→ on_bar(index=2)
→ on_intrabar(index=2)
    規則 說明
    在 on_bar 送出的委託最快在下一根成交 不會以當根收盤價成交。market_ioc 以下一根的開盤價成交
    on_position 在 on_bar 之前執行 成交發生在撮合階段（步驟 2），所以同一根 K 棒內 on_position 先執行，on_bar 後執行
    停損停利每根 K 棒呼叫一次 set_STL 等方法依當前持倉重算出場價並更新委託，不呼叫就不會更新
    新成交持倉的浮動損益從下一根開始計入 剛成交的持倉，在同一根的 on_bar 中讀到的 global_unrealized_point 尚未包含它

    多週期時，同一個時點的觸發順序是先執行所有子週期訊號（on_bar2／on_bar3…），最後才是 base 週期的 on_bar。對標商品（on_other）在同一時點先於主商品執行。

    row 的欄位

    feed_data() 餵入時，row 的 key 如下（含一個自訂欄位 mysig）：

    ['DateTime', 'Open', 'High', 'Low', 'Close', 'Volume', 'mysig',
 'time', 'ts', 'char', 'char1', 'index']
    key 說明
    DateTime 這根 K 棒的收盤時間（pd.Timestamp）
    Open／High／Low／Close／Volume 開高低收量。即使 feed_data() 傳入的是中文欄名，key 一律是英文
    index K 棒序號，從 0 開始，等同在 row_list 中的位置
    ts DateTime 的 epoch 秒（float）
    time 14 碼字串 'YYYYMMDDHHMMSS'
    char／char1 主圖／副圖指標的 dict，等同 self.char／self.char1
    Settlement 該筆所屬的結算日。feed_tick_df() 且 need_settlement=True 時才有；feed_data() 要以 columns=['Settlement'] 帶入
    自訂欄位 以 columns=[...] 指定帶入，保留原本的欄名（例如外部算好的訊號欄）

    feed_data() 的 args 只指定哪一欄是時間、開、高、低、收、量，row 中的 key 一律為英文 Open／High／Low／Close／Volume。

    feed_tick_df() 的 key 順序為：

    ['time','Open','High','Low','Close','Volume', <columns>, 'DateTime','Settlement','index','ts','char','char1']

    判斷當根是否為結算日：row['DateTime'] == row['Settlement']。

    持倉與委託

    Position

    on_position 的參數 P，以及 self.positions 的 value。

    欄位 說明
    index 進場的 K 棒序號
    entry_time 進場時間
    entry_qty 原始進場數量
    entry_price 進場價格
    max_earn 持倉期間的最高獲利（點數）
    max_loss 持倉期間的最大虧損（點數）
    rule 造成進場的規則名稱
    unrealized_pnl 當前未實現損益
    current_qty 當前剩餘數量（部分平倉後小於 entry_qty）
    uid 這筆持倉的唯一識別碼，出場單以 match_uid=P.uid 綁定

    Order

    self.orders 的 value，欄位為 index、rule、datetime、add_qty、trade_price、trade_type、uid、match_uid。 self.orders 的 key 是 (rule, match_uid)。

    狀態屬性

    策略內可以直接讀取下列屬性。損益以點數計，不含交易稅與手續費；實際金額見 generate_report() 的報表。

    屬性 說明
    self.global_qty 全域總持倉。正為多、負為空、0 為空手
    self.global_realized_point 全域已實現損益（點數，不含稅費）
    self.global_unrealized_point 全域未實現損益，隨行情變動
    self.positions 持倉 dict，key 為 uid，value 為 Position
    self.orders 未成交、未取消的委託，key 為 (rule, match_uid)
    self.row_list 所有已收盤 K 棒的 dict 串列，row_list[-1] 為當根
    self.row 當根 K 棒的 dict，等於 row_list[-1]
    self.stats 依規則名稱累計的統計，見下方「self.stats」
    self.char／self.char1 主圖／副圖指標，見下方「繪圖指標」
    self.tick_map 最小跳動單位表 [(價格上限, tick), ...]。預設為股票規格 [(10,0.01),(50,0.05),(100,0.1),(500,0.5),(1000,1.0),(inf,5.0)]；台指期在 on_init 設為 [(np.inf, 1)]
    self.PriceType 委託型別常數，見 下單與成交
    self.Condition 下單與停損停利的入口，見 下單與成交
    self.Ind 技術指標，見 技術指標與參數最佳化。類別屬性，所有策略實例共用同一份
    core.log 委託生命週期的 DataFrame，type 欄為 new／update／cancel／deal

    保留屬性

    上表的屬性由框架維護，例如 self.row 每根 K 棒都會被換成當根資料，存入的其他內容不會保留。 自訂狀態請使用其他名稱（例如 self.my_feat），不要覆寫 row、row_list、char、positions、orders、global_qty、stats、Condition、PriceType、Ind。

    比例下單（數量填 0～1）時，沖銷後的持倉可能留下約 1e-17 的浮點殘量，框架以 1e-9 的容差處理。自行比較口數時，同樣以容差判斷，不要直接用 == 0。

    self.stats

    self.stats['規則名'] 會自動建立該規則的統計：

    欄位 說明
    open_count 進場次數
    open_qty 累計進場口數
    close_count 平倉次數
    current_qty 目前剩餘口數
    realized_pnl 該規則累計已實現損益（點數）
    continue_wins 連勝／連敗：正數為連勝、負數為連敗，勝敗切換時歸為 ±1
    records {出場規則名: [次數, 口數, pnl]}

    在策略內讀取 self.stats，可以依戰績調整下一筆的數量。以下在連勝 2 次以上時把數量加倍：

    class WinStreak(bt.Core):
    def on_init(self):
        self.base_qty = 1

    def on_bar(self, row):
        wins = self.stats.get('bk', {}).get('continue_wins', 0)
        qty = self.base_qty * 2 if wins >= 2 else self.base_qty   # 連勝 2 次就加倍
        if row['mysig'] and self.global_qty == 0:
            self.Condition.Global(True, qty, 0, self.PriceType.market_ioc, None, 'bk')

    以 2330、MA20 訊號、1000 個交易日執行，52 次進場中有 13 次因連勝放大為 2 張，rp.trade_detail 的 qty 分布為 {1: 38, 2: 13}。連勝到 3 之後輸一次，continue_wins 變為 -1：

    輸出
    2023-01-09  wins=2   qty=2
2023-03-17  wins=3   qty=2
2023-03-21  wins=-1  qty=1

    core.stats 與 self.stats 是同一個物件，回測結束後從外部讀取 core.stats 會得到相同的累計結果。

    部位結清後的處理

    on_position 在開倉、加倉、部分平倉時觸發，完全平倉時不觸發。以下例子在 index=0 買 2 口、index=2 賣 1 口、index=4 賣出剩餘部位，on_position 只觸發 2 次：

    輸出
    on_position 觸發 2 次: [(1, 'bk', 2, 2), (1, 'bk', 1, 2)]
期末 global_qty = 0

    要在部位結清後執行動作，在 on_bar 中讀取 self.stats[rule] 的 close_count／realized_pnl／continue_wins，或在回測後查看 rp.trade_detail。

    自訂出場單與內建停損停利

    出場單不帶 match_uid 時，會依序沖銷現有持倉。策略同時使用 set_STL 等內建停損停利或反手時，自訂的平倉單（例如數量 -self.global_qty）要等下一根才撮合；若持倉在這之前已被停損或反手平掉，這張單仍會成交，並反向開出一筆新倉（rp.trade_detail 的 entry_rule 會是這張出場單的規則名稱）。

    這種情況下，自訂平倉單在 on_position 中以 match_uid=P.uid 綁定個別持倉；持倉不存在時，框架會自動撤銷綁定的委託。寫法見 下單與成交。

    繪圖指標 self.char／self.char1

    寫進 self.char／self.char1 的數值會畫在 core.show_monitor() 與 rp.dashboard() 個股分析頁的 K 線上：self.char 疊在主圖，self.char1 畫在副圖；名稱含 hist 的指標畫成柱狀。

    self.char['fast'] = fast[-1]      # 主圖
self.char['slow'] = slow[-1]

    撰寫步驟

    1. 選擇餵資料的方式：單一週期用 feed_data(df)；需要 on_bar2 多週期訊號，或要以小週期 K 線模擬盤中、讓停損觸發順序更精確時，用 set_tick_period() ＋ feed_tick_df()。見 資料與週期。
    2. 在 on_init 設定參數：要用參數最佳化搜尋的參數存成 self.xxx，bt.Tools.optimize() 才能從外部覆寫。
    3. 期貨在 on_init 設定 self.tick_map = [(np.inf, 1)]，否則委託價依股票的跳動單位調整。
    4. 暖身期不下單：指標資料不足時（例如 len(close_list) < window）回傳無訊號。
    5. 每個 Global() 使用不同的 rule 名稱。同一組 (rule, match_uid) 重複呼叫是更新同一張委託。不要使用內建停損停利保留的 STL／PFT／DS／TGT。
    6. 進場條件加上部位檢查：self.global_qty == 0（只進場一次）或 < 1（可反手），否則每根 K 棒都會再下單。
    7. 停損停利的四個 set_* 方法在每根 K 棒無條件呼叫，不放在 if 內。
    8. 依標的設定 config() 的 unit、fee、tax_short、保證金，見 商品設定與績效報告。
    9. 檢查結果：rp.report 看 KPI、rp.trade_detail 逐筆核對、rp.dashboard() 看圖。
    10. 參數最佳化：把策略包成回傳 generate_report(...) 結果的函式，交給 bt.Tools.optimize()，見 技術指標與參數最佳化。

    框架訊息

    訊息 說明

    [加載] feed_tick／feed_tick_df／feed_other 對應的餵資料方法已可使用
    [警告] 主商品第2周期 D 但沒定義 on_bar2, 略過 設定了多週期，但沒有實作對應的 on_barN
    [警告] 對標第1周期 60 但沒定義 on_other, 略過 設定了 set_other_period()，但沒有實作 on_other
    [警告] tick ... 落在 period 交易時段之外，已忽略 資料時間不在 period 指定的交易時段內
    [警告] 主商品資料時間 ... 早於前一筆 ...，已忽略 時間早於已餵入資料的部分被略過
    [警告] ...: DateTime 沒有依時間遞增，已自動排序後才餵入 資料未依時間排序，框架已自動排序。建議檢查資料來源
    【'開始下載':XXX ,freq=1】／【下載完成】 bt.Tools.get_*_ohlc() 正在下載資料（同一商品只下載一次）

    時序相關的警告見 資料與週期。

    錯誤處理

    錯誤訊息 原因 處理方式
    RuntimeError: 還沒有任何 K 棒就下單了 (self.row 是空的)。
    Condition.Global 只能在 on_bar / on_intrabar / on_position 裡呼叫，
    on_init 只用來初始化參數。    		 在 on_init 中呼叫了 Condition.Global() 把下單移到 on_bar、on_intrabar 或 on_position
